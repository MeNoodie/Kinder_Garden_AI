# Contributing to Kinder Garden AI

Thanks for helping improve Kinder Garden AI. Contributions of all sizes are welcome: bug reports, documentation fixes, tests, and new features.

## Before you start

- Search existing issues and pull requests to avoid duplicates.
- Open an issue first for significant changes, so the approach can be discussed.
- Do not include API keys, tokens, local `.env` files, generated audio, or other private data in commits.

## Local development

1. Fork the repository and create a feature branch.
2. Follow the setup steps in the [README](README.md).
3. Make a focused change with clear names and comments where they add value.
4. Test the backend and frontend paths affected by your change.
5. Update documentation when behavior or configuration changes.

## Pull requests

Use a concise title and describe what changed, why it changed, how you tested it, and any configuration or API-key requirements.

Keep pull requests small and focused. Be respectful and constructive in reviews; participation is governed by the [Code of Conduct](CODE_OF_CONDUCT.md).
